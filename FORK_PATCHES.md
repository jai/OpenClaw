# Google Chat fork patch stack

This branch carries the shared gateway stack for OpenClaw 2026.10.4, built on upstream OpenClaw `main` at `85507ee907`. Layers 1–8 end at `b9574d47d1`; layers 9–11 merge through [#17](https://github.com/jai/OpenClaw/pull/17), [#19](https://github.com/jai/OpenClaw/pull/19) and [#23](https://github.com/jai/OpenClaw/pull/23). Each commit below is a separate layer so an upstream refresh can drop a layer as soon as upstream supplies the same behavior. The branch does not change other channel plugins.

This inventory covers the Google Chat overlay deployed to VOC. Fork `main` has independent prompt-reconciler and CI changes that are not in this overlay or the current VOC runtime. Reconcile those separately before promoting this branch to fork `main`; do not replace fork `main` with this branch.

## Notes

Layer 9 ports the proven [Linus delivery fix](https://github.com/jai/OpenClaw/commit/1c0088cc2) onto this exact shared runtime base. It keeps the eight earlier layers, including existing thread-session keys, batched routing, explicit-send formatting, partial receipts, and group-only session suffix parsing. It supersedes final-placeholder replacement and the final-edit custody branches in layers 4–6 and 8 because the activity message never becomes the answer. Progress edit failures, including rate limits, are logged without blocking the final answer. Partial or ambiguous final sends retain feedback.

Explicit final message sends and automatic final answers are separate visible messages; explicit progress sends (`final: false`) fold into the activity message while it is open. A queued turn retains its activity message until its source delivery or settlement. Activity writes and narrative progress edits finish before the final send. Per-thread room sessions remain opt-in; existing Zola session keys remain intact.

For the next refresh, fetch upstream `main`, branch from its exact commit, replay the required layers in order, resolve conflicts without dropping per-thread session routing, and regenerate the config baseline. Compare each layer against upstream before retaining it. Validate the message-action formatter and partial sends, A/B/A thread sessions, activity status/edit/cleanup and chronological final placement, batched routing, and rejected/ambiguous edits with the focused Google Chat tests and a full build. Deploy only a verified, pinned commit after saving runtime/config/state backups; check both Google Chat accounts on a shared gateway and use a real inbound Chat turn to verify visible behavior.
